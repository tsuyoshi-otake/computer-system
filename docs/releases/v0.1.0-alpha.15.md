# Computer System v0.1.0-alpha.15

This fifteenth public alpha improves the practical guest command-line workflow
without crossing the guest/host execution boundary. It completes a bounded
CS-Linux data-processing set and pipeline/redirection explanation, brings the
portable CS-DOS command line closer to a familiar MS-DOS 6.2 workstation, and
aligns the managed Python/Perl CS486 cost model with recorded real-BDS evidence.

This remains a prerelease. Back up a stopped world before testing it; persisted
data compatibility is not guaranteed between development alphas.

## Highlights

### Guest-owned Linux dataflow

- CS-Linux now exposes bounded `grep`, `rg`, `cut`, `sort`, `uniq`, `tr`,
  `xargs`, and `jq` workflows alongside the existing `sed` and `awk` surface.
  Each command reads guest files or guest standard input only; no command starts
  a host shell, process, filesystem scan, regular expression engine, or
  JavaScript filter.
- The shell distinguishes file descriptors 0/1/2, applies redirects in lexical
  order, supports `|`, `|&`, `<`, `>`, `>>`, `2>`, `2>>`, `2>&1`, `&>`, literal
  here-documents, and `tee`, and retains bounded pipeline backpressure, EOF, and
  SIGPIPE behavior.
- The canonical manual and static Pages source explain what reaches a pipeline,
  when stderr remains separate, and the deliberately bounded compatibility
  limits.

### CS-DOS 6.2-style essentials

- CS-DOS now includes `FIND`, `SORT`, `FC`, and `COMP`, with DOS CRLF output,
  explicit guest-file/stdin behavior, and fixed input, record, output, and
  comparison ceilings (Issue #126).
- `CHOICE` and `PAUSE` now use the terminal's guest-owned key-prompt lifecycle.
  A selected key supplies one-based `ERRORLEVEL`; Ctrl+C, disconnect, shutdown,
  invalid input, and batch continuation each reach an explicit outcome.
- The DOS command processor deliberately remains narrower than Linux: it retains
  its sequential guest spool for `|`, `<`, `>`, and `>>`, while `2>`, `2>&1`,
  `|&`, `&>`, `LESS`, native COMMAND.COM behavior, and native `.COM`/`.EXE`
  execution fail visibly rather than being approximated.

### Managed CS486 accounting

- Perl control flow and managed operations execute behind one production
  `Cs486Process`/allowlisted guest-syscall boundary. Python and Perl share one
  deterministic operation-aware tariff for dispatch, type checks, loads, stores,
  collection and iterator work, string traversal, and numeric representation
  costs.
- The included real-BDS comparison provenance keeps guest CPU cycles distinct
  from host wall time and records deterministic 66 MHz CS486DX2 observations.

## Bounds and compatibility

- Every new command remains guest-owned, capacity-limited, and explicit about
  unsupported syntax. Guest input never reaches PowerShell, `cmd.exe`, Node
  child processes, host compilers, or host files.
- This is not a full POSIX/Bash/jq/Perl conformance claim, an MS-DOS binary
  emulator, or the Phase 6 release-hardening milestone.
- Targeted real writer-owned browser/GDK interaction evidence for the newly
  added CS-DOS commands has not been rerun. The host contract and isolated BDS
  integration are verified; that remaining interaction check is retained in
  Issue #126 and the manual verification checklist.

## Packaging

The Behavior Pack moves to 0.1.19 because the generated guest runtime script
changed. The Resource Pack remains at 0.1.18 because no shipped artwork,
localization, geometry, texture, or JSON UI changed; the Behavior Pack continues
to declare that matching Resource Pack dependency.

The release attaches deterministic Behavior/Resource `.mcpack` files, the
combined `.mcaddon`, and `SHA256SUMS.txt`. GitHub Pages remains a static manual,
not a Web Terminal endpoint.
