# Computer System v0.1.0-alpha.13

This thirteenth public alpha is a focused host-throughput maintenance release.
It removes redundant shell-job synchronization from the high-frequency CS-Linux
process CPU-accounting path while preserving exact guest cycle charges, process
revisions, lifecycle transitions, output, and modeled guest timing.

This remains a prerelease. Back up a stopped world before testing it; persisted
data compatibility is not guaranteed between development alphas.

## Highlights

- Removed the unconditional job-table traversal performed for every live process
  that reported a positive CPU-cycle delta (Issue #120).
- Kept `account_cycles` authoritative: process `cpuCycles`, process
  `changedTick`, and the OS runtime revision still advance exactly as before.
- Defined job `changedTick` as the tick of the last job lifecycle transition.
  Pure CPU accounting no longer freezes a replacement running-job record with
  the same state on every tick.
- Preserved dependent synchronization for stop, continue, exit, and all other
  lifecycle transitions. Job state, lifecycle tick, and exit status remain
  exact.
- Kept the optimization deliberately narrow. It does not add a PID-to-job index
  and does not introduce a generic same-state shortcut that could suppress a
  different transition's dependent effects.

## Cost model

Let `A` be the processes with a positive cycle delta in a tick and `J` the job
records. The removed work was `O(A × J)` because each accounted process scanned
the complete job table. CPU accounting itself is now `O(A)` with respect to
jobs. The configured 64-process and 32-job capacities are worst-case bounds, not
a claim that every tick reaches them.

The 32-job boundary test accounts all 32 processes, proves exact accumulated
cycles and runtime revision increments, and retains the identity, state, and
`changedTick` of every job record. The ordinary lifecycle test then proves that
STOP, CONT, and exit still replace the matching job with the exact stopped,
running, and done states.

## Alpha boundaries

- Issue #16 still owns the real-BDS 1/10/20/32-computer load matrix. That matrix
  and repeated before/after profiling were not rerun for this release, so no
  numerical end-to-end speedup is claimed.
- The optimization changes host work only. It does not change modeled CPU
  cycles, instruction counts, scheduler admission, guest output, or guest
  timing.
- A PID-to-job index remains deferred unless post-change profiling proves a
  residual lookup bottleneck.
- This is not the project's Phase 6 release-hardening milestone, and it is not
  long-duration multiplayer acceptance.
- Guest networking, package management, unrestricted processes/threads/sockets,
  and CS Windows remain future work.
- The separately maintained reduced NetHack prototype remains excluded from
  release completion percentages.

## Packaging

The Behavior Pack moves to 0.1.17 because its generated script bundle changed.
The Resource Pack stays at 0.1.18 because no shipped artwork, localization,
geometry, texture, or JSON UI changed.
