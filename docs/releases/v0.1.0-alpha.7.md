# Computer System v0.1.0-alpha.7

This seventh public alpha makes production guest CPU admission configurable,
adds a configurable Computer-affine runtime-worker pool, improves the CS486
interpreter's dominant execution path, and removes guest NetHack compilation
from Bedrock module startup.

This remains a prerelease. Back up a stopped world before testing it; persisted
data compatibility is not guaranteed between development alphas.

## Highlights

- Set the shipped production admission rate to approximately one half of each
  persisted nominal CPU clock: 400,000 cycles/tick for CS386SX 16 MHz, 825,000
  for CS486DX 33 MHz, and 1,650,000 for CS486DX2 66 MHz at 20 TPS.
- Added the strict, build-validated Behavior Pack setting `guestRealtimeDivisor`
  so pack authors can select the ratio without changing persisted hardware
  identity or guest timing semantics.
- Raised the bounded per-runtime scheduler ceiling to 1,650,000 instructions and
  the per-execution-resource ceiling to 1,650,000 instructions per tick. Each
  worker and the local Bedrock lane remain finite without serializing unrelated
  resources behind one host-global counter.
- Added a configurable fixed-size runtime-worker pool for managed BDS, with two
  workers by default and a strict 1-through-16 range. Stable Computer-ID
  affinity applies equally to CS386SX, CS486DX, and CS486DX2. Worker count
  changes aggregate multi-Computer host capacity, never guest CPU identity,
  clock, cycle debt, or per-tick admission.
- Predecoded immutable instruction timing and control-flow metadata once per
  executable and CPU model. The fixed host benchmark improved by 1.39x to 1.58x
  while retaining identical checksums and modeled guest-cycle counts.
- Added host wall-time observability to scheduled `run --stats` and
  `python --stats`, including guest cycles per host second and the modeled
  real-time ratio. Host elapsed time remains observational only.
- Moved the immutable stock NetHack executable to a deterministic generated
  payload checked at build time. Production BDS startup no longer compiles,
  links, validates, or serializes NetHack during module evaluation.
- Finalized admitted Linux and DOS guest RAM when shell construction fails, so
  failed power-on and safe-boot attempts do not retain volatile memory.

## Install

1. Back up the stopped target world.
2. Download and open `computer-system-0.1.0-alpha.7.mcaddon`.
3. Activate the imported Computer System Behavior Pack; its dependency activates
   the matching Resource Pack.
4. Use Minecraft Bedrock Edition 1.26.30 or later in the 1.26 release line.

The release ships Resource Pack 0.1.18 and Behavior Pack 0.1.12. Separate
Behavior and Resource `.mcpack` files and `SHA256SUMS.txt` are provided for
independent verification and import.

Live Web Terminal features require the source release and the local companion;
GitHub Pages remains documentation only.

## Alpha boundaries

- The one-half rate is an admission ceiling, not a host throughput guarantee.
  Multi-Computer contention can reduce observed progress.
- The managed runtime-worker build requires the irreversible Beta APIs
  experiment for its private server-admin/server-net loopback transport. It
  never enables that experiment silently on a preserved world; stop BDS, make a
  full world backup, and obtain explicit operator consent first. Only a newly
  generated disposable acceptance world beneath the current user's temporary
  directory is enabled automatically.
- Issue #106 retains the measured Rust/WASM batch-executor prototype as future
  work. Native DLL and hypervisor execution are not Bedrock-compatible paths.
- This is not the Phase 6 hardened release and is not long-duration multiplayer
  acceptance.
- Persisted world/data compatibility is not guaranteed between development
  alphas.
- Guest networking, package management, dynamic loading, unrestricted
  processes/threads/sockets, and CS Windows remain future work.
- The preserved reduced NetHack prototype remains excluded from release
  completion percentages.

## Verification

- `npm run validate` passed formatting, ESLint, TypeScript, 303 Vitest files
  with 2,499 tests, all hosted-C and generated NetHack payload checks, the
  production Bedrock pack, and the 16-chapter Pages build.
- The deterministic two-worker benchmark retained 42/42 compared executions at
  the shipped 1,650,000-instruction capacity per worker. Ten CS486DX2 Computers
  measured 1.9854x end-to-end speedup, 99.27% worker efficiency, a 10.67 ms
  median batch-average per tick, and a 40.0 MiB benchmark-pool RSS increase.
- A maximum 1,650,000-instruction CS486DX2 slice measured 15.99 ms median and
  17.84 ms p95 with the shipped statistics setting on the same Node.js 26.2.0
  host. This is host-only margin evidence, not a real-BDS tick guarantee.
- A disposable real-BDS managed-worker roundtrip assembled and executed an
  isolated CS486 program through the authenticated loopback worker, then
  returned actor and request counts to zero. Real-browser checks showed truthful
  `W2/2` on CS386SX/CS-DOS and `W1/2` on CS486DX2/CS-Linux without console
  warnings or errors.
- The 2,000,000-instruction, seven-sample host benchmark retained each model's
  checksum and guest-cycle count. Median throughput improved from 38.23 to 60.51
  million instructions/s on CS386SX, 29.36 to 40.86 on CS486DX, and 29.13 to
  40.89 on CS486DX2 on the same Node.js 26.2.0 host.
- A preserved-world BDS restart reached `CS_STORAGE_MIGRATION complete` without
  the prior module-startup watchdog interruption. The preserved world contained
  no placed Computers, so no live guest/Web Terminal rate assertion was made.
