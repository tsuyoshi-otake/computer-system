# Computer System v0.1.0-alpha.8

This eighth public alpha adds an optional managed-BDS runtime-worker pool that
offloads guest CPU execution from the Bedrock main thread, admits a bounded
CS486 hot-execution loop for register/ALU/branch-heavy guest code, raises the
shipped production admission rate, improves the CSIR optimizer, and evaluates
(without adopting into production) a gated Rust/WebAssembly batch-executor
prototype for the CS486 interpreter.

This remains a prerelease. Back up a stopped world before testing it; persisted
data compatibility is not guaranteed between development alphas.

## Highlights

- Added a configurable, fixed-size managed-BDS runtime-worker pool (two Node
  worker_threads by default, a strict 1-through-16 range) that offloads
  isolated CS executable processes from the Bedrock main thread over an
  authenticated loopback transport. Stable Computer-ID affinity applies equally
  to CS386SX, CS486DX, and CS486DX2; worker count changes aggregate multi-user
  host capacity only, never guest CPU identity, clock, cycle debt, or per-tick
  admission. This is an operator-selected build: it requires the world's
  irreversible Beta APIs experiment, is never enabled silently on a preserved
  world, and normal release packs remain Beta-free.
- Admitted a bounded CS486 hot-execution loop inside the interpreter for
  decoded register, integer ALU, compare, conditional-branch, and direct-jump
  instructions, prepared once per immutable executable. Memory, stack,
  call/return, multiply/divide, syscall, output, halt, and fault-capable
  instructions keep the existing per-instruction path and its exact modeled
  timing.
- Raised the shipped production admission rate from one-hundredth to
  approximately one-half of each persisted nominal CPU clock: 400,000
  cycles/tick for CS386SX 16 MHz, 825,000 for CS486DX 33 MHz, and 1,650,000 for
  CS486DX2 66 MHz at 20 TPS, with matching per-runtime and per-execution-resource
  scheduler ceilings. Each worker and the local Bedrock lane own an independent
  round-robin cursor so an uneven Computer-to-worker distribution cannot bias
  long-term service.
- Improved the CSIR optimizer with algebraic and power-of-two strength
  reduction, block-local common-subexpression elimination, and bounded leaf
  inlining, fixing a pre-existing register-allocator loop-backedge liveness bug
  that CSE exposed.
- Prototyped and measured (Issue #106 Phase 4) independent Rust and
  AssemblyScript WebAssembly batch-executors sharing one host ABI against the
  TypeScript CS486 interpreter. The Rust variant cleared the project's ≥2x
  median host-cost adoption gate in all 18 benchmark matrix cells with zero
  differential-equivalence divergences; AssemblyScript did not. Neither variant
  is integrated into the production execution path in this release.

## Install

1. Back up the stopped target world.
2. Download and open `computer-system-0.1.0-alpha.8.mcaddon`.
3. Activate the imported Computer System Behavior Pack; its dependency activates
   the matching Resource Pack.
4. Use Minecraft Bedrock Edition 1.26.30 or later in the 1.26 release line.

The release ships Resource Pack 0.1.18 and Behavior Pack 0.1.12. Separate
Behavior and Resource `.mcpack` files and `SHA256SUMS.txt` are provided for
independent verification and import.

Live Web Terminal features require the source release and the local companion;
GitHub Pages remains documentation only. The managed runtime-worker pool is an
additional operator-run mode of that same local companion; it is not required
for ordinary single-worker Web Terminal use.

## Alpha boundaries

- The one-half rate is an admission ceiling, not a host throughput guarantee.
  Multi-Computer contention can reduce observed progress.
- The managed runtime-worker build requires the irreversible Beta APIs
  experiment for its private server-admin/server-net loopback transport. It
  never enables that experiment silently on a preserved world; stop BDS, make a
  full world backup, and obtain explicit operator consent first. Only a newly
  generated disposable acceptance world beneath the current user's temporary
  directory is enabled automatically.
- Issue #106's Rust/WASM batch-executor prototype cleared its adoption gate on
  measured host cost and proven equivalence, but production integration into
  the managed runtime-worker pool is a separate, later decision; the shipped
  execution path is still the TypeScript interpreter. Native DLL and hypervisor
  execution remain not Bedrock-compatible paths.
- This is not the Phase 6 hardened release and is not long-duration multiplayer
  acceptance.
- Persisted world/data compatibility is not guaranteed between development
  alphas.
- Guest networking, package management, dynamic loading, unrestricted
  processes/threads/sockets, and CS Windows remain future work.
- The preserved reduced NetHack prototype remains excluded from release
  completion percentages.

## Verification

- `npm run validate` passed formatting, ESLint, TypeScript, 307 Vitest files
  with 2,529 tests, all hosted-C and generated NetHack payload checks, the
  production Bedrock pack, and the 16-chapter Pages build.
- The deterministic two-worker concurrency benchmark retained 42/42 compared
  executions at the shipped 1,650,000-instruction capacity per worker. Ten
  CS486DX2 Computers measured 1.9854x end-to-end speedup, 99.27% worker
  efficiency, a 10.67 ms median batch-average per tick, and a 40.0 MiB
  benchmark-pool RSS increase. A disposable real-BDS managed-worker roundtrip
  assembled and executed an isolated CS486 program through the authenticated
  loopback worker, then returned actor and request counts to zero.
  Real-browser checks showed truthful `W2/2` on CS386SX/CS-DOS and `W1/2` on
  CS486DX2/CS-Linux without console warnings or errors.
- Hot-burst admission held identical cycles, registers, instruction address,
  RAM, output, process state, and cache/bus/pipeline-flush counters against the
  per-instruction reference across all three CPU models (223 tests); an
  alternating A/B check against the same source with hot-burst forced off
  measured a branch/ALU corpus at 1.34x to 1.50x, while a mixed memory/stack
  corpus had no eligible hot-burst entry and showed no claimed speedup. Full
  detail is recorded in `docs/issues/issue-16-cs486-hot-burst.md`.
- The Issue #106 wasm prototype's differential-equivalence check reported zero
  divergences over 361,693 comparisons across 516 seed/profile/instrumentation
  configurations, with the comparator's sensitivity independently demonstrated
  by a forced negative check. The full A/B matrix, adoption-gate verdict, and
  Rust-versus-AssemblyScript selection rationale are recorded in
  `docs/issues/issue-106-wasm-batch-executor.md`. A `COMPUTER_SYSTEM_WASM_PROBE`
  run against a live BDS session confirmed the Bedrock Script API exposes no
  `WebAssembly` global, so any wasm benefit is scoped to the Node-side managed
  runtime-worker pool.
- CSIR optimizer changes retained unchanged dynamic guest evidence (executed
  instruction counts, guest cycles, and checksums) on the regenerated hosted-C
  archive and NetHack payloads; `osStorageImage` capacity checks pass at the
  tuned inlining limits.
