# Computer System v0.1.0-alpha.3

This third public alpha integrates the desktop CRT into each Computer block,
adds the second-generation CS-DOS memory architecture, strengthens CS486 process
ownership, and refines the fixed-cell Web Terminal and DOS editor experience.

This remains a prerelease. Back up a stopped world before testing it; persisted
data compatibility is not guaranteed between development alphas.

## Highlights

- Replaced the standalone Monitor probe with cream all-in-one Deskpro-style
  Computer and Advanced Computer blocks.
- Added purpose-built block geometry, face textures, and inventory artwork for
  desktop and portable machines.
- Added the authoritative CS-DOS physical memory map with conventional, UMB,
  HMA, and XMS regions plus atomic CONFIG.SYS admission.
- Added deterministic paragraph-aligned allocation, snapshot-backed MEM output,
  and exact resident/process RAM ownership.
- Added CS executable v3 declarations for stack, heap, and auxiliary residency
  while retaining bounded compatibility for v1/v2 executables.
- Hardened compile, foreground, background, debugger, disconnect, detach, and
  shutdown finalization so guest RAM grants release exactly once.
- Refined EDIT, CS QBASIC, WorkBench, vi, and nano limits, dialogs, diagnostics,
  keyboard handling, and shared terminal interaction.
- Improved Web Terminal input admission, pointer/cell mapping, fixed-grid
  scaling, VGA presentation, session feedback, and multi-viewer behavior.
- Removed the decorative green outline around the focused terminal display while
  preserving the guest caret and textual CONTROL/input state.

## Integrated machine presentation

Desktop and Advanced Computer now carry their CRT, keyboard-facing drive panel,
and power controls in one placeable block. The upper chassis remains a strict
rectangular cuboid, the screen is nearly flush rather than a visible thick slab,
and Computer/Advanced expose one/two compact 3.5-inch drives respectively.

The generated Resource Pack uses purpose-built 16 px block faces and bounded
derived inventory icons rather than applying the authored isometric plates as UV
textures. The release ships Resource Pack 0.1.16 with Behavior Pack 0.1.6.

## CS-DOS memory architecture v2

One boot-scoped memory manager owns the complete physical address map and
reconciles every resident/process allocation with the guest RAM ledger. The
modeled portable map separates conventional memory, reserved video/ROM
apertures, optional UMBs, HMA, and extended/XMS memory.

CONFIG.SYS is planned and validated without side effects. Invalid configuration
commits no partial layout and boots an explicit degraded-low profile while
AUTOEXEC remains observable. DEVICEHIGH tries UMB first and reports its
conventional fallback; DOS=HIGH admits the complete high-resident set or loads
it low with a diagnostic.

MEM, MEM /C, MEM /D, and MEM /F consume one immutable snapshot. Free extents,
largest blocks, module placement, physical totals, and ledger totals therefore
share one source of truth. Allocation and snapshot work are bounded by the
number of admitted extents rather than modeled RAM bytes.

## Process and toolchain ownership

CS executable v3 declares the cs-flat32-v1 stack, heap, and auxiliary physical
residency. Admission reserves the exact working set before process construction.
Legacy v1/v2 programs receive the historical currently-free exclusive grant so
two old executables cannot silently share the same physical remainder.

Python compilation and execution, startup programs, shell jobs, and debugger
replacement now converge on explicit finalizers. Completion, failure,
interruption, terminal disconnect, session detach, and machine shutdown return
their owned reservations to the exact baseline once.

Structured guest toolchain transcripts keep display text and diagnostic
navigation derived from the same records. CS486 object/executable validation,
stack bounds, typed function signatures, and Python extension linking reject
incompatible or malformed inputs before execution.

## Editors and Web Terminal

DOS EDIT, CS QBASIC, PWB/CS C/C++, CSASM, vi, and nano share bounded document
limits and terminal interaction rules. Dialog composition, file browsing,
selection, pointer admission, command insertion, completion, symbol navigation,
and diagnostic traversal remain inside the sandboxed guest environment.

The browser keeps the fixed 80x25 hardware grid, IBM VGA presentation,
cursor-positioned input, selection-aware copy, and authoritative writer/viewer
state. It reports input and lifecycle state textually, keeps stale/viewer/range
input non-mutating, and no longer draws a bright green rectangle around the
whole terminal when its transparent input owns focus.

## Install

1. Back up the stopped target world.
2. Download and open `computer-system-0.1.0-alpha.3.mcaddon`.
3. Activate the imported Computer System Behavior Pack; its dependency activates
   the matching Resource Pack.
4. Use Minecraft Bedrock Edition 1.26.30 or later in the 1.26 release line.

Separate Behavior and Resource `.mcpack` files and `SHA256SUMS.txt` are provided
for independent verification and import.

The archives contain the Minecraft packs. Live Web Terminal features require the
source release and the local companion; GitHub Pages remains documentation only.

## Alpha boundaries

- This is not the Phase 6 hardened release and is not long-duration multiplayer
  acceptance.
- Persisted world/data compatibility is not guaranteed between development
  alphas.
- The DOS map is a deterministic Computer System ABI, not DPMI, EMS, native x86,
  BIOS interrupts, or DOS COM/EXE compatibility.
- CS C/C++ remains a documented subset, not ISO C++, Microsoft C/C++ 7.0, MASM,
  OMF, or a native host toolchain.
- User-program graphics/TUI/input/audio APIs, source-level debugging, guest IP
  networking, package management, and CS Windows remain future work.
- Live-player disconnect/Portable observation and long-duration multi-user
  acceptance remain explicit manual checks.
