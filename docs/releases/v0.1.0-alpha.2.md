# Computer System v0.1.0-alpha.2

This second public alpha expands the implemented Phase 2 preview with a complete
CS-DOS development workflow, a more robust Web Terminal, structural guest
resource accounting, and configurable CRT presentation.

This remains a prerelease. Back up a stopped world before testing it; persisted
data compatibility is not guaranteed between development alphas.

## Highlights

- Completed the CS-DOS 1.0 EDIT, CS QBASIC 1.0, CS ASM 1.0, and CS C/C++ 1.0
  development workflow.
- Added mixed ASM/C/C++ Program Lists, bounded guest-only preprocessing,
  transactional builds, listings/maps, and exact artifact ownership.
- Added bounded editor configuration, completion, symbols, definitions, and
  guest-shell commands to DOS editors and `vi`.
- Hardened Web Terminal handoff, reconnect, range, writer ownership, input
  acknowledgement, blocked-consumer handling, and frame rendering.
- Added exact-session MCP activation, bounded logical TUI inspection/input, and
  machine-checkable screen verification that does not return screen text.
- Added structural Portable CS-DOS disk, HDD-time, and transient RAM accounting.
- Added a centered Web Terminal frame plus configurable CRT and curved-glass
  presentation with a 5% default curvature value.
- Captured a reproducible 1-, 5-, and 32-session routing baseline for future
  transport optimization.

## CS-DOS development environment

The DOS product identity is consistently **CS-DOS 1.0**, with the original
Computer System toolchains presented as **CS ASM 1.0**, **CS C/C++ 1.0**, and
**CS QBASIC 1.0**.

`CSASM`, `CSCC`, `CSCPP`, and `PWB` open the full-screen WorkBench. F7 builds a
persistent `.CSX`, Ctrl+F5 runs the last valid build, and Shift+F5 builds and
runs. The instruction debugger provides bounded continue, trace,
register/disassembly display, and current-EIP breakpoints.

EDIT, CS QBASIC, and WorkBench share explicit dirty-buffer, Open, Save As,
overwrite, external-change, removable-media, and close decisions. The 80x25 DOS
layout includes a guest-only A:/C: 8.3 browser, canonical File and Display
dialogs, fixed-column `DIR`, the DOS palette, and the licensed WebPlus IBM VGA
8x16 browser font. Compact 51x19 layouts remain available.

`CS PROGRAM LIST 1.0` supports ordered ASM/C/C++ sources, authored objects,
include paths, defines, deterministic incremental fingerprints, transactional
objects/executable/listing/map output, ownership-scoped Clean, exact Run Last
state, and bounded diagnostic navigation.

The C/C++ frontend includes a bounded guest-only token preprocessor with quoted
and angle includes, object/function macros, conditionals, rescanning,
stringification, token pasting, and Linux/DOS `-I`/`-D`/`-U` parity. Unsupported
directives and ABI constructs fail explicitly.

## Editor configuration and language services

DOS EDIT, CS QBASIC, PWB/CS C/C++, and CSASM share bounded Options pages for
syntax, line numbers, indentation, whitespace, wrapping, tabs, completion,
language detection, and definition sources. `C:\EDITOR.INI` has atomic, bounded
`[common]`, `[edit]`, `[qbasic]`, `[pwb]`, and `[csasm]` configuration.

Ctrl+Space completion, Ctrl+Shift+O symbols, F12 definitions, and Alt+Left
history use lazy revision-cached indexes. Candidate counts, buffers, includes,
scanned bytes, symbols, and jump history are bounded; no host process or LSP is
started.

`vi` adds bounded `~/.vimrc` or `C:\_VIMRC` options, completion cycling,
symbols, definition/back navigation, indentation controls, and guest-only `:!`,
`:!!`, and `:r !` commands. Parent shell and editor ownership are restored on
every terminal path.

## Web Terminal reliability and MCP evidence

One-use handoff creation waits for the exact Bedrock session to become ready.
The exchange is same-origin and tokens remain out of URLs, browser history, and
BDS logs. Reconnect work is single-flight and bounded, stops on terminal
authentication results, and honors `Retry-After`.

Editor input uses a bounded FIFO and leaves the queue only after correlated
Bedrock admission. Replaced sessions, disconnects, timeouts, BDS stop, and
companion stop each have one explicit finalization owner.

Terminal frames apply atomically, unchanged Computer revisions avoid another
cell-grid capture, and sessions on one Computer share the captured frame. The
browser collapses rapid updates to the latest animation frame and preserves
unchanged row DOM nodes. Blocked NDJSON consumers retain only the newest
meaningful terminal/control state.

The MCP companion can activate an exact Computer through a server-authorized
debug principal and verify exact writer ownership without a connected player or
exposed one-use URL. `bds_verify_tui_screen` returns bounded pass/fail evidence
for geometry, cursor, color grids, literal constraints, same-row groups, and
vertical runs without returning the captured rows or search literals. Secret
prompts, stale writers, malformed criteria, and capacity overflow fail
explicitly.

## Display options

The complete fixed 80x25 display frame stays centered horizontally and
vertically in CLI and TUI states. The browser surface has no internal scrollbar;
guest-rendered EDIT, `vi`, and WorkBench scrollbars remain canonical terminal
cells.

The former CRT toggle is now an **Options** dialog with independent controls:

- CRT profile: **Off**, **Subtle**, **Arcade**, or **Shadow Mask**
- Screen shape: **Flat** or **Curved Glass**
- Curvature: **0-30%** in 1% steps, with **5%** as the default

A new page starts at Arcade, Flat, and 5%. Curvature is enabled only for Curved
Glass and updates immediately. The same bounded value drives SVG displacement
and inverse TUI pointer mapping.

Presentation state is tab-local and resets on reload. It does not change
terminal cells, colors, selection, copied text, or the bounded row-diff render
path. The displacement map is deterministic and generated from the same
coordinate model used by pointer mapping.

## Guest-resource fidelity

Portable CS-DOS uses structural FAT16-like accounting: a 20 MiB volume,
2,048-byte allocation units, bounded root/directory metadata, and atomic
full-disk rejection. `DIR` reports logical bytes while free-space and quota
accounting charge allocated units.

HDD service preserves the complete byte count through bounded sequential
requests. A transient `GuestRamLedger` accounts for host-implemented guest
residency, with bounded leases released on close, cancel, failure, disconnect,
completion, and shutdown. These values model guest resources; they do not
measure the JavaScript host heap.

## Install

1. Back up the stopped target world.
2. Download and open `computer-system-0.1.0-alpha.2.mcaddon`.
3. Activate the imported Computer System Behavior Pack; its dependency activates
   the matching Resource Pack.
4. Use Minecraft Bedrock Edition 1.26.30 or later in the 1.26 release line.

Separate Behavior and Resource `.mcpack` files and `SHA256SUMS.txt` are provided
for independent verification and import.

The archives contain the Minecraft packs. Live Web Terminal features require the
source release and the local companion; GitHub Pages remains documentation only.

## Alpha boundaries

- This is not the Phase 6 hardened release and is not long-duration multiplayer
  acceptance.
- Persisted world/data compatibility is not guaranteed between development
  alphas.
- Desktop Chrome is the primary display target. Mobile-specific polish is not
  part of alpha.2 acceptance.
- CRT settings are browser presentation, not a guest display mode, framebuffer,
  or ShaderGlass runtime dependency.
- Guest IP networking, routes, DNS, package management, `ping`, and `ss` remain
  unavailable.
- CS C/C++ remains a documented subset, not ISO C++, Microsoft C/C++ 7.0, MASM,
  OMF, or native DOS COM/EXE compatibility.
- User-program graphics/TUI/input/audio APIs, source-level debugging, and CS
  Windows remain future work.
- Remaining connected curved-pointer, multi-viewer wall-time, and physical GDK
  checks are not implied by host tests.
